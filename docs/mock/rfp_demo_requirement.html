본 제안요청서는 충청북도 바이오 원재료 생산·가공·유통 및 최종 소비자를 위한 상품 조회 플랫폼의 핵심 요구사항을 기술하고 있으며, 계약 체결 후 분석·설계 단계의 공식 과업 범위 기준이 됩니다.

Ⅰ. 사업 개요
1. 추진 배경 및 필요성

□ 국내 바이오 건강식품 시장은 고부가가치 산업으로 지속 성장하고 있으나, 원재료 원산지 위변조 및 허위 표시 라벨링 유통 사례가 빈번하게 발생하여 소비자 신뢰 저하 및 선의의 생산 농가 피해가 발생하고 있음.

  • 식품의약품안전처 조사 결과 건강기능식품 제조 감시 중 원재료 성분규격 및 표시기준 위반 건수가 다수 적발되어 원재료 출처 및 가공 단계의 투명한 이력관리 체계가 시급히 요구됨.
  • 홍삼·인삼 등 대표 바이오 특산물의 원물 수확부터 가공, 유통, 완제품 판매에 이르기까지 위·변조가 불가능한 블록체인 분산원장 기반의 실시간 추적 체계 구축이 필수적임.

□ 최종 소비자 및 바이어의 신뢰 확보를 위한 원스톱 상품 조회 서비스의 필요성 증대

  • 소비자가 제품 패키지의 QR코드를 스캔하여 원재료 시험성적서, 유통 경로, 인증 정보를 즉시 조회할 수 있는 대국민 포털 서비스 제공 필요.
  • 지역 특산품 판촉 행사 및 온라인 기획전 등 대규모 접속 폭증 시에도 중단 없이 조회 서비스를 제공할 수 있는 신뢰성 높은 아키텍처 수립이 요구됨.
2. 서비스 내용 및 사업 범위
가. 바이오 원재료 생산·유통 전과정 블록체인 이력 관리
  • 원물업체, 가공업체, 유통업체, 제조업체 등 공급망 참여자 간 데이터 상호 검증 및 원장 기록.
  • 공인시험기관의 진세노사이드 함량, 잔류농약 검사 등 품질성적서의 스마트 컨트랙트 등록.
나. 대국민 상품 조회 포털 및 보안 QR 서비스 구축
  • 대국민 상품 조회 포털 WEB/WAS 서비스 개발 및 모바일 최적화 반응형 웹 구현.
  • 식별코드(보안 QR) 발급, 스캔 검증 및 조회 트랜잭션 처리.

신속한 대응 품질 문제 또는 회수 사유 발생 시 유통 경로 역추적 시간을 기존 수일에서 수 초 이내로 단축

Ⅲ. 제안요청 내용
1. 제안요청 개요
  • 사 업 명 : 블록체인 기반 바이오 원재료 이력관리 및 상품 조회 플랫폼 구축

  • 주요 과업 : 원재료 이력관리 분산 노드 구축, 데이터 통합관리 시스템, 대국민 상품 조회 포털, 대용량 트래픽 대응 아키텍처 구현

서비스 계층 대국민 상품 조회 포털, 보안 QR 발급·검증 모듈, 이력 추적 대시보드, 통계 모듈

요구사항 분류 기능 요구사항 요구사항 번호 SFR-001
요구사항 명칭 원재료 이력 데이터 수집 및 블록체인 등록
상세 설명 [정의] 참여기업별 원재료 생산·가공·유통 이력 정보 등록 및 분산원장 연계
[세부내용]
o 충청북도 내 바이오·인삼·홍삼 참여 기업의 생산 일자, 원산지, 가공 공정 정보를 입력받아 블록체인에 영구 기록하여야 함.
o 온체인(On-Chain) 분산원장과 오프체인(Off-Chain) 관계형 데이터베이스 간 데이터 동기화 체계를 구성하여야 함.
o 원재료 검사 정보 또는 유통 단계별 이력에 변동이 발생한 경우 필요한 경우 관리자에게 알림을 제공하고 시스템에 반영하여야 함.
요구 산출물 기능 명세서, 데이터베이스 설계서
요구사항 분류 기능 요구사항 요구사항 번호 SFR-002
요구사항 명칭 시험성적서 및 이력 데이터 수정 관리
상세 설명 [정의] 오기재된 이력 정보 및 성적서 재발급 시 데이터 보정 및 이력 추적
[세부내용]
o 공인시험기관의 성적서 재발급 등 정정 사유가 발생한 경우, 승인 절차를 거친 후 데이터를 수정할 수 있어야 함.
o 데이터 수정 시 기존 원본 이력과 정정 사유, 변경 일시를 감사 로그(Audit Log) 형태로 별도 보관하여 위변조를 방지하여야 함.
o 분산원장에 이미 등록된 트랜잭션의 경우, 덮어쓰기가 아닌 보정 트랜잭션 추가 발행 방식으로 무결성을 유지하여야 함.
요구 산출물 프로그램 사양서, 감사로그 명세서
요구사항 분류 기능 요구사항 요구사항 번호 SFR-003

o 소비자가 모바일 기기로 패키지 QR코드를 스캔하여 제품의 생산지, 가공일자, 시험성적서를 원클릭으로 확인할 수 있어야 함.
o 소비자가 모바일 QR코드를 스캔하여 조회할 때, 온·오프체인 데이터 정합성 검증을 거쳐 오류 없이 정상적으로 처리되어야 함.
o 웹 표준을 준수하여 다양한 모바일 브라우저(iOS Safari, Android Chrome 등)에서 동일한 화면을 제공하여야 함.
요구 산출물 화면 설계서(UI/UX), 프로그램 소스코드

2. 성능 요구사항 (PER : Performance Requirement)
요구사항 분류 성능 요구사항 요구사항 번호 PER-001
요구사항 명칭 시스템 응답 성능 일반
상세 설명 [정의] 웹/WAS 시스템의 안정적이고 신속한 기본 트랜잭션 응답 성능 보장
[세부내용]
o 사업대상 시스템의 성능을 고려한 애플리케이션 최적화 방안을 제시하여야 함.
o 대상 시스템에 대하여 24시간 365일 안정적 운영 지원 및 성능 모니터링 체계를 수립하여야 함.
o 시스템 구축 중 APM 도구를 적용하여 병목 구간을 사전 분석 및 조치한 후 시스템을 오픈하여야 함.
요구 산출물 성능 시험 결과서, 모니터링 구성 방안서
요구사항 분류 성능 요구사항 요구사항 번호 PER-002
요구사항 명칭 대용량 상품 조회 성능 보장
상세 설명 [정의] 마케팅 프로모션 및 접속 폭증 상황에서의 대용량 상품 조회 부하 대응
[세부내용]

o 시스템은 많은 사용자의 동시 상품 조회 요청에 빠르게 응답해야 한다. 부하 시험은 10분 동안 수행하며 성공 응답 비율은 99.9% 이상이어야 한다.

o 대용량 데이터의 조회, 검색, 추출 등 서비스 이용에 병목이 발생하지 않도록 캐시 계층(Redis 등)을 적극 활용하여야 함.
o 트래픽 급증 시 시스템 장애 방지를 위한 부하 분산 및 서킷 브레이커 방안을 마련하여야 함.
요구 산출물 부하 시험 결과서, 성능 튜닝 보고서
요구사항 분류 성능 요구사항 요구사항 번호 PER-003
요구사항 명칭 서비스 가용성 및 무중단 운영 보장
상세 설명 [정의] 서비스 무중단 운영 및 고가용성(HA) 인프라 구축
[세부내용]
o 특정 웹/WAS 또는 노드 장애 발생 시에도 자동 페일오버를 통해 서비스가 중단 없이 지속되도록 이중화 구성하여야 함.
o 클라우드 인프라 장애에 대비하여 정기 데이터 백업 체계를 수립하고 연간 가용성 99.9% 이상을 목표로 관리하여야 함.
o 정기 점검 및 애플리케이션 배포 시 무중단 롤링 업데이트 방식을 적용하여야 함.
요구 산출물 인프라 구성도, 가용성 보장 계획서

3. 인터페이스 요구사항 (INR : Interface Requirement)
요구사항 분류 인터페이스 요구사항 번호 INR-001
요구사항 명칭 외부 유통망 및 시험기관 연계 API 제공
상세 설명 [정의] 이력 데이터의 실시간 동기화를 위한 RESTful API 제공
[세부내용]
o 유통 플랫폼 및 참여 제조사 ERP와의 안전한 데이터 교환을 위한 표준 REST API 인터페이스를 설계 및 제공하여야 함.
o API 호출 인증 및 권한 관리를 위한 API Key 및 토큰 기반 보안 체계를 적용하여야 함.
o 대외 연계 기관과의 네트워크 단절 또는 API 응답 지연 등 장애 발생 시 적절히 처리하고 재시도하여야 함.

4. 데이터 및 보안 요구사항 (DAR, SEC)
요구사항 분류 데이터 요구사항 요구사항 번호 DAR-001
요구사항 명칭 공공 데이터 표준 관리 및 원장 데이터 구조화
상세 설명 [정의] 공공 데이터 표준 지침 준수 및 블록체인 원장 데이터 모델 수립
[세부내용]
o 행정안전부 공공기관 데이터 표준 지침에 따라 공통 코드, 용어 사전, 도메인 정의서를 작성하여 일관성을 유지하여야 함.
o 온체인 트랜잭션 페이로드는 최소화하고 대용량 첨부 문서(성적서 사본 등)는 해시값 검증 기반의 외부 스토리지에 분리 저장하여야 함.

요구사항 명칭 플랫폼 정보보호 체계 및 이력 데이터 보안
상세 설명 [정의] 정보보호 관리체계 수립 및 플랫폼 저장·전송 데이터 보안
[세부내용]
o 행정안전부 SW 개발보안 가이드(시큐어 코딩)를 준수하여 웹 취약점을 사전에 점검 및 조치하여야 함.
o 전송 구간 암호화(TLS 1.3 이상) 및 데이터베이스 암호화(AES-256)를 적용하여야 함.
o 플랫폼에 저장되는 참여기업의 제조 원가 및 공급망 중요 데이터는 안전하게 관리하여 외부 유출을 방지하여야 함.
